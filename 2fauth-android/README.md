# 2FAuth Android

原生 Android 两步验证应用（Kotlin + Jetpack Compose）。它首先是一个独立的验证器：没有服务器也能用；连接你自己的 2FAuth 服务器后，还可以同步验证码、查看云端验证码。界面风格、主题和卡片样式与网页端一致。

## 三种验证码

| 类型 | 密钥在哪里 | 说明 |
|---|---|---|
| 仅本机 | 只在这台手机上 | 新添加的验证码默认是这一类。二维码、链接都在手机上解析，任何内容都不会发送到服务器。 |
| 同步 | 手机和服务器各一份 | 登录后自动同步。网页端改过的账户，手机下次连上时以服务器为准；手机上的修改在服务器未改动时推送上去。HOTP 计数器两边取较大值。 |
| 云端 | 只在服务器上 | 手机只拿到短效验证码，拿不到密钥（服务器会拒绝把密钥发给手机令牌）。在“云端”页查看。 |

- 仅本机 → 同步：需要先通过指纹、面容或锁屏密码验证，密钥才会上传。把“新验证码保存为”改成“同步”时也要验证一次。
- 同步 → 仅本机：服务器删除它的副本。
- 同步 → 云端：服务器保留，手机删除密钥。
- 云端 → 同步：只能在网页端账户编辑里打开“同步到手机端”（手机令牌无权这样做）。
- 网页端删除一个同步的验证码时，手机不会跟着删掉，而是把它改成“仅本机”并标记“已从服务器删除”，避免密钥丢失；在网页端把它改成仅云端时，手机会删除自己的副本。

首页只显示前两类，数据在启动时从本机加密文件一次读入内存，验证码在手机上每秒计算，打开即可用，离线也能用。

## 安全

- 本机验证码保存在一个文件里，用 Android Keystore 中的密钥加密（AES-GCM），并排除在系统备份之外。
- 登录后应用会创建一个“设备令牌”：服务器只允许它调用手机需要的接口，不能导出账户、读取云端验证码的密钥、管理令牌或 SSH 密钥。退出登录时它会被吊销。1.0 版本留下的完整权限令牌，在升级后第一次启动时会自动换成设备令牌。
- 应用锁（指纹、面容或锁屏密码）、默认禁止截屏、复制的验证码标记为敏感并在 30 秒后清除。
- 自签名证书：确认指纹后只信任这一张证书，证书变化就拒绝连接。

## 界面

- 15 套主题（与网页端相同），可自定义强调色，浅色主题会自动切换状态栏颜色。
- 五种卡片样式：经典色条、顶部微光、双层边框、胶囊标签、便当盒，与网页端一致。
- 动画：数字滚动、平滑倒计时、卡片依次滑入、按压反馈、复制时闪光、页面切换。可在设置里关闭。
- 服务图标支持 SVG（服务器上的图标都是 SVG，1.0 版本无法显示）。仅本机验证码的图标从公共图标库获取，图标库会看到服务名，可在设置里关闭。
- 扫码使用 CameraX 实时识别，画面只在手机上处理，不保存。

## 更新

管理员在网页端「管理 → Android 应用」上传新版本 APK（版本名、版本号、更新说明）。手机每天检查两次，发现新版本会发通知；点开后下载，校验 SHA-256，再交给系统安装器。只有用同一个签名密钥签名的安装包才能覆盖安装。未登录时，应用向 `BuildConfig.UPDATE_SERVER`（默认 `https://2fa.aios3.com`）检查更新。

网页首页提供最新版本的下载链接：`/download/android/latest.apk`。

## 构建

需要 JDK 17 和 Android SDK（platform 35、build-tools 35）。

```bash
cd 2fauth-android
echo "sdk.dir=$ANDROID_HOME" > local.properties
./gradlew testDebugUnitTest    # OTP 计算对照 RFC 4226 / 6238 测试向量
./gradlew assembleDebug        # 包名 app.twofauth.android.debug
./gradlew assembleRelease      # 需要 keystore.properties
```

正式包的签名信息写在 `keystore.properties`（不进仓库）：

```properties
storeFile=/path/to/2fauth-release.jks
storePassword=...
keyAlias=2fauth
keyPassword=...
```

以后发布更新必须使用同一个签名密钥，否则手机上无法覆盖安装。请备份好密钥文件和密码。

最低支持 Android 8.0（API 26），目标 Android 15（API 35）。
